# V0.4 · 分辨率适配与减少人工输入

基线 main：1165782c24b860e764dbed237dc4bb73c7bd8324。目标：不要求每次换分辨率重新输入坐标；先完善离线识别，不引入驱动前置条件。

## 实施边界

新增 adaptive_hud.py（自动尺寸、边缘/中心锚定、多尺度局部搜索）、temporal.py（连续帧候选确认）、对应本地接口和自适应页面。原固定ROI接口、位移测量及Context契约保持兼容。WRITE_SCOPE沿用AGENTS.md；不修改其他仓库、不上传用户媒体。

首次建立模板时提供带标签的参考图，并在参考图上框一次稳定图标；后续查询不用填写目标图坐标或分辨率。模板可主动导出到本机文件、下次导入。没有预装WARDOGS识别模型，不把搜索最高分直接当正确状态。

## 两种分辨率问题不能混淆

HUD适配只负责找到图标，不改原始截图、测量轨迹或鼠标counts。UI坐标使用原图物理像素，显示缩放仅用于预览。匹配使用统一比例模板，位置由最近的边缘/中心锚定估计后局部搜索；禁止将21:9整图硬拉成16:9。

鼠标响应与视角测量仍绑定精确Context。分辨率、FOV、瞄准倍率、灵敏度或输入后端改变，不沿用旧验证结论。即使同FOV下像素位移随图像尺寸变化，也不能直接把鼠标输入按像素比例放大。

## 识别契约

两到八个有效且标签不同的参考图，同一layout_id（游戏构建、语言、HUD样式族；不再将分辨率作为布局ID的一部分）。参考ROI以原图像素标注，8..256像素；各参考可提供各自ROI。允许参考图和待测图分辨率不同。输入必须是原始游戏画面，不自动推断手机拍屏透视、黑边或窗口裁剪。

多尺度搜索使用有限的尺度候选和局部窗口，自动估计目标位置；模板缺纹理、跨标签分差不足、多个位置难以区分、低相似度均返回unknown。图标样式、语言、HUD布局或游戏版本实际变化需要新参考，不凭相同声明认定已兼容。分数不是概率，候选始终auto_execution_eligible=false。

## 连续帧

批次最多24帧，总解码像素不超过9000万；逐帧真实时间戳必须显式提供，不从文件名/上传顺序猜时间。连续3帧且跨越至少80ms才能输出稳定候选；新标签立即撤销旧标签，unknown立即失效，间隔超过100ms或几何配置变化重新积累。同一图片重复不会提高确认度，自匹配参考图不能充当独立确认。

这是离线有时标样本的稳定化，不是自动屏幕采集，不连接StatePlayback或驱动。稳定器只能减少瞬态跳变，不能纠正连续的系统性误识别。真实停止延迟需要另外测量。

## 验证计划

合成HUD覆盖720p/1080p/1440p/4K、宽屏边缘锚定、HUD缩放、位置漂移、歧义、缺失、布局不匹配、无纹理、重复帧、坏时钟、间隔和分辨率突变。UI测试覆盖框选坐标/自动读尺寸/导入导出/过期结果拒收。本地测试、包装检查、远端工作流分别记录，不冒称游戏/Windows硬件验收。

## 后续自动化

1. 本机选择一段录像，自动读取帧时间戳、抽样和整理状态候选，只有不确定片段需要确认。
2. 游戏真实参考包与不同会话验证；UI自动推荐框仅作为候选，不把背景变化当姿态图标。
3. 将response/fit/refine/validate组成向导，自动做质量检查、版本比较和结果保留。
4. 实时采集、实际输入后端和设备响应最后适配；不得借HUD跨分辨率匹配取消曲线Context门禁。

参考：OpenCV matchTemplate与resize官方文档；Microsoft DPI/物理坐标官方文档。匹配方法是工程候选，不是已训练的视觉模型。
