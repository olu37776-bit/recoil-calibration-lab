# V0.5 产品化操作 / 验收计划

基线 main: 69acf43d4debcec62c3d3af97a1fe73076728189。用户要求完整可用的产品，而非继续增加离线实验页。

本轮 WRITE_SCOPE 沿用 AGENTS.md；允许新增 tools/ 下打包入口、桌面启动器、工作台、会话存储和 Windows 标准输入适配。V0.4 禁止实际输出的阶段限制在本轮只对**用户明确授权的受控校准与手动监督执行**放宽；不接反作弊，不提权、不读游戏内存，不做检测规避或自动点击。

## 交付闭环
1. 自动打开本机工作台、环境自检、保存会话和配装；源代码启动与 Windows 便携包使用同一入口。
2. 导入现有 Trial ZIP，或 Windows 前台窗口内采集；响应标定至少2轮，训练至少3轮。
3. response / fit / refine / validate 在统一工作台调用原算法；训练/验证隔离、历史版本保留。
4. 明确区分演示、模型预测、真实录制回放。模拟示例永远不能启用实际输出。
5. 真实输出仅标准 Windows SendInput（不是雷蛇驱动宏）；默认关闭、选定窗口、明确授权、F7按住作为独立使能、开镜和左键同时按住、F8/Esc急停、焦点/尺寸/曲线时长/调度中断即停。换弹等按键是中断信号，不冒充完整游戏状态识别。
6. 受控验证允许有限候选回放；常规手动监督执行必须有匹配同一Profile的 recorded replay验证结果。没有未验证的全游戏自动模式。
7. 采集只在明确选定的前台窗口内进行；原图不默认落盘，测量数据存本机用户目录，不上传。
8. Windows包必须由Windows runner构建，自检必须运行打包后的程序；SHA256与构建提交绑定。尚未成功出包不得称已有EXE。

## 边界
自动识别姿态/弹量/配件的游戏模板与实机准确率仍未有证据。不把手动监督执行模式称为成熟的全自动游戏产品。操作者改变游戏内设置时必须重新选择/采集配装；程序不能仅靠窗口大小发现所有设置变化。系统拒绝输入时停止并报错，不绕过。

## 验证
保留旧测试；新增存储/导入/端到端算法/执行门禁/Windows结构定义/启动自检/打包测试。HTTP测试使用直连本机、连接超时与线程化服务。远端分测试文件设置硬超时和保存诊断；旧任务日志404，原因未知，不以猜测代替根因。
