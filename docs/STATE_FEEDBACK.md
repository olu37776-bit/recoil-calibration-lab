## Observation完整快照

`observed_s, context_id, pressed, ads, focused, item_kind, action, fire_mode, ammo, confidence, source` 必须全部提供，不用上一帧填缺项。未知布尔值、ammo用null；未知分类用unknown。

`source`: synthetic / manual_annotation / recorded_hud / input_inference。只有输入事件推测的状态不允许输出。manual_annotation用于离线标注，不等于自动识别。recorded_hud只是外部来源声明，不证明正确率。

时间必须有限、非负、严格前进；观察不允许来自未来或倒序；陈旧超过100ms停止。该100ms是本项目实验上限，不是任何驱动或游戏的延迟承诺。低于0.85的质量分数停止，该分数不代表概率。

放行条件同时满足：已释放后重新按下；窗口有焦点；已开镜；手持枪；action=ready；ammo>0；fire_mode=auto；精确Context有曲线。缺项、冲突或未确认均阻断。半自动/点放模式没有被自动当作全自动。

开火按住期间被阻断，即使后续观察恢复也不能自动续发；必须先释放。切姿态、切枪、换配件全部改变Context，不会用旧曲线冒充新配装。曲线末尾停止，不循环、不外推、不补发积压动作。

StatePlayback使用RecordingSink，没有系统输入。输出reason可审计；原Playback保持兼容，CLI仍是录制回放，不从新HUD端点直接启动。

## HUD候选比较

`POST /api/hud-compare`输入：field（pose/action/ads/ammo）、layout_id、image、2..8张带label/layout_id的references、同一ROI、threshold（默认0.90）与margin（默认0.08）。

固定8..512像素ROI，在灰度均值图上计算去均值归一化相关；不滑动搜索、不隐式缩放、不OCR、不扫进程。要求全部原始分辨率和声明布局一致、标签不冲突、参考ROI有纹理。单张6MiB/1200万像素，整批4800万解码像素，沿用32MiB HTTP上限。

最高分太低、与第二名太接近或观察ROI无纹理则unknown。相同参考图配不同标签直接拒绝。若待测图就是参考图，标记self_match=true，不算独立验收。

**归一化相关度不是准确率，也不是可靠的完整状态分类器。** 未见过的状态可能与参考很像。当前端点只返回候选，`auto_execution_eligible=false`固定为false；没有将单张识别结果接入回放。ammo只比较empty/nonempty，既不恢复剩余弹量，也不把未匹配到empty当成nonempty。

## GUI和验证

首页“状态实验室”进入 `/state.html`。可运行16种合成场景并导出决策轨迹；待测参考图只送本机，不持久化、无默认上传。

验证：原算法回归 + 门禁变更/时钟/配置/恢复测试 + 合成截图候选/歧义/无纹理/尺寸错误测试 + HTTP路由；浏览器范围单独记录。没有自动准确率、Windows硬件、WARDOGS游戏或独立审查通过结论。

下一阶段用同分辨率原始游戏截图标注姿态/动作/开镜/空仓，留出不同采集会话做验证，测误放行与停止延迟；完成后再讨论实时采集/输入适配。单帧分类的高分不能直接作为全场景启用依据。
