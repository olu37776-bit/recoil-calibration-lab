# 核心数据与执行契约（V0.2 保留 V0.1 算法）

## 1. Context

`weapon`、`attachments`、`dpi`、`sensitivity`、`ads_sensitivity`、`zoom`、`resolution`、`fov`、`pose`、`game_build`、`input_backend` 必填。对完整 JSON 计算 SHA-256，作为配置指纹。

驱动以后才接，但 **输入后端是标定条件**。后端改变后必须重新测量“输入单位→画面位移”；不能认为罗技、雷蛇、系统事件的一个单位天然相同。分辨率、倍率、姿态、配件和灵敏度改变同样失效。附件列表顺序也是指纹一部分，导入方应固定顺序。

## 2. Trial

一个 `.json` 元数据文件对应同目录的 `.csv`。字段必须严格按照此顺序：

```text
t_s,dx_px,dy_px,uy_counts,confidence,valid
```

`t_s` 是秒，从零开始且严格递增；首个样本是操作者指定的射击前参考帧/首发对齐点。`dx_px` / `dy_px` 是相对该帧的累计相机位移，屏幕右/下为正。静止背景的运动方向与相机相反。它不是弹孔坐标、实际命中率或枪械动画。

`uy_counts` 是实际已经执行的累计垂直输入单位，不是“期望发送”的值。视频无补偿导入仅允许明确声明未进行任何压枪操作，因此填写 0。带补偿回放必须使用同步输入记录，不能从画面猜测输入。

`confidence` 属于观测估计的[0,1]质量分数，不代表概率校准后的置信水平；`valid` 只能是0/1。至少10个样本、持续至少0.2秒、相邻间隔不超过0.1秒、所有质量分数至少0.65。任一坏区间拒绝整轮，不跨丢跟踪区间拼接累计位移。

必填元数据：`schema_version=1`、`run_id`、`session_id`、`context`、`phase`、`source`、`provenance`、`csv`、`content_sha256`。可使用 `save_trial` 建立并校验数据。

`phase` 是 `response` / `train` / `validation`。`source` 是 `synthetic` / `recorded`。`recorded` 表示有记录来源，不自动证明是指定游戏、未经人工干预或真实无作弊环境。

`provenance.capture_sha256` 标识原始录像。没有该字段时，以 `session_id` 为采集边界。同一原始录像的训练片段和验证片段不能算独立采集。

## 3. Response

测量模型：`dy(t) = recoil(t) + gain * u(t-latency)`。

`gain_px_per_count` 可以为正或负，但不能为零；通过至少两轮无射击、含正负方向输入的记录稳健拟合。`latency_s` 在本版由操作者提供，默认0；**没有实现自动延迟识别**。模型假设当前状态附近局部线性。不符合残差门禁时拒绝标定。

拟合不自动修复错误单位/错误延迟，也不会用分辨率和DPI直接换算出未测量的 gain。

## 4. Profile

曲线是从零开始的**累计垂直输入**，保存为时间节点与 counts 的分段线性插值。横向位移会测量，但 V0.1 不生成横向补偿。

初始拟合至少三轮同配置、同来源训练数据；先扣除已执行输入的估计效果，再取跨轮中位数，识别可重复漂移。默认初次只补偿70%，后续用新训练数据小步修正。限制更新幅度和输入速度，拒绝高随机性样本。

曲线在完整可观测区间内有效。拟合采用各训练轮共同覆盖的时长；验证必须覆盖完整曲线。禁止外推未观测的后段连射。

响应延迟在评估中计入。本版不在开火前预先发送输入；有延迟时起始误差不能被“提前开火前补偿”掩盖。

## 5. 验证与回退

至少三个验证 Trial；与训练在 run_id、session_id、原始 capture hash 和数据 content hash 上隔离。离线把旧输入效果去掉再加候选效果，只是模型预测。

当记录的实际累计输入与候选曲线在比较网格上的偏差不超过0.51 count时，按整数输入量化容差识别为回放；否则只能标成预测。即使源是 recorded，也不能排除操作者错误声明，真实验收需人工检查原始数据。

评估完整过程的 RMS、峰值、前中后三段 RMS；默认要求每轮比无补偿基线改善至少50%、绝对峰值不超过20px。与旧版本比较时不允许每轮 RMS 明显变差。

`SIMULATED_REPLAY`：合成回放。`RECORDED_REPLAY`：有匹配输入记录的录制回放。`MODEL_PREDICTION`：没有实际执行候选的反事实预测。

`KEEP_CANDIDATE_IN_LAB` 只表示本地实验门禁通过；`PREDICTION_ONLY` 不允许当成实测通过；`KEEP_PREVIOUS` 表示候选未过门禁。程序不会自动覆盖旧 profile 文件来实现版本替换，操作者保留旧文件；没有实现自动版本注册中心。`game_verified` 始终为 false。

## 6. 驱动接口与回放状态机

```python
class MotionSink(Protocol):
    def move(self, t_s: float, dx_counts: int, dy_counts: int) -> None: ...
```

`t_s` 是该次连射的相对秒数，move 是增量而非累计位置。当前只有 `RecordingSink`，写入内存事件列表。`Playback.tick()` 由外层提供单调时钟、按键状态、ADS、窗口焦点和配置指纹。

程序启动时要求先释放开火键；松开立即停止。丢失焦点、离开ADS、配置变化、时钟异常或调度间隔超过100ms，锁定为等待释放状态；不会恢复后补发积压位移。累计值取整后发增量，避免每次小数截断累积误差。超过曲线长度后停止，按住不自动重启下一轮。

将来任何驱动适配器都必须复用这些约束，并重新标定 Response。没有进程注入、检测规避或游戏内目标识别接口。
